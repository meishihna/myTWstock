# 回測引擎 JS 版 — 使用說明（給 Coverage 前端）

瀏覽器**現場計算**任一上市個股的 10 進場 × 9 出場 × 5 確認層 = **450 組**回測，
數值與資料端預先算好的 `signals/{code}.json` **逐格完全相同**。

- 純函式、**零外部相依**、ESM，Node 與瀏覽器共用
- 交付檔案：`backtest.mjs`、`pyround.mjs`、`chipsbits.mjs`（三個模組，零外部相依）
  + `ex-factors.json`（442 KB，**全市場：上市 + 上櫃**）、`chips-bits.json`（889 KB）
- 效能：單檔 **450 組**（5 年約 1,240 根）→ **中位 73.3ms / 最慢 81.9ms**；
  只跑 90 組時中位 19.4ms（Node 24，單執行緒同步）

---

## 1. 快速上手

```js
import { runBacktest } from "/scripts/backtest.mjs";

const bars = await fetchRawBars("2330");            // 原始（未還原）日K，由舊到新
const ex   = (await fetch("/data/ex-factors.json").then(r => r.json())).events["2330"] || [];

const out = runBacktest(bars, {
  exEvents: ex.map(([date, ratio]) => ({ date, ratio })),
});

out.combos      // 90 組（未給 confirm 時）：{ s:[...統計], t:[[...逐筆], ...] }
out.buyhold     // { "總報酬%": .., "最大回撤%": .. }
out.meta        // 期間／交易日數／規則名稱／欄位定義／出場原因表
out.prices      // 還原後 OHLCV（可直接畫圖，免另外抓）
```

輸入 `bars` 每根：`{ d: "2026-07-31", o, h, l, c, v }`，`d` 為 ISO 日期字串，**由舊到新**、
無成交日已剔除。`v` 為成交股數。

輸出的 `combos[].s` / `combos[].t` 欄位順序，與 `signals-index.json` 的
`comboFields` / `tradeFields` 完全一致 —— 前端渲染程式可共用。

## 2. ⚠️ 餵錯資料 = 6.7% 的組合會對不上

| 餵給 `runBacktest` 的資料 | 結果 |
|---|---|
| **原始 STOCK_DAY 日K + `exEvents`** | ✅ 與 `signals/{code}.json` **逐格相同**（已驗 23 檔 / 10,350 組 / 0 差） |
| `prices/{code}.json`（已還原、**四捨五入到 4 位**） | ❌ 2,250 組中 **150 組（6.7%）統計不同**，涉及 20/25 檔 |

（6.7% 是在「無」確認層的 2,250 組上量的；加上確認層只會更多，不會更少。）

原因：`prices/*.json` 是**顯示用**資料，存檔時已捨入到小數 4 位。第 5 位以後的差異
會讓「收盤 vs 均線」這類比較在極少數 K 棒上翻面，一旦翻面就提早／延後出場，整筆報酬與
後續交易全部走偏。**不是誤差累積，是分支翻轉。**

→ 現場計算請一律抓原始日K；`prices/*.json` 只拿來畫圖。

## 3. 資料來源

### 原始日K（上市）— 瀏覽器可直接抓

```
https://www.twse.com.tw/rwd/zh/afterTrading/STOCK_DAY?date={YYYYMM}01&stockNo={code}&response=json
```

- 官方端點回 `Access-Control-Allow-Origin: *` → **前端可直接 fetch，不需代理**
- **逐月**回傳，5 年視窗需 **61 個月 = 61 次請求**／檔 → 請節流（建議序列化 + 間隔）
  並以 `localStorage` / `Cache API` 快取（歷史月份不會再變，只有當月要更新）
- 欄位順序：`[日期, 成交股數, 成交金額, 開, 高, 低, 收, 漲跌, 筆數]`
  日期是民國 `115/07/31`；收盤為 `--` / 空 / `0.00` 的無成交日要剔除
- 只取 `date ≤ 錨定日` 的列，才能與資料端同視窗

### 除權息還原因子 — `ex-factors.json`

```json
{ "schema":"ex-factors/1", "years":[2021,2026],
  "events": { "2330": [["2021-09-16", 0.99...], ...] } }
```

**2,104 檔、12,846 事件、442 KB（全市場：上市 6,658 + 上櫃 6,188）。**
`ratio = 除權息參考價 / 前一日收盤`，**原始精度不可自行捨入**
（先捨入再累乘，實測 28,412 根裡 6,990 根還原價會偏，最大 0.002 → 同樣造成分支翻轉）。

還原規則：某根 K 的因子 = 所有「**除息日 > 該根日期**」之事件比率的累乘，OHLC 乘上該因子，
**成交量不還原**。這段 `adjustBars()` 已內建，前端只要把事件陣列丟進 `exEvents` 即可。

資料涵蓋 6 年、**上市 + 上櫃**（上市來源 TWT49U、上櫃來源 exDailyQ）。過期需重新產生（資料端負責）。

⚠️ **以代號為鍵，不分市場**：轉上市（上櫃→上市）的 8 檔在兩個市場都有事件，取**聯集**。
這是對的且無副作用 —— 轉上市前的事件日期都早於該檔在新市場的第一根 K，
而因子只累乘「除息日 > 該根日期」的事件，所以那些事件不會被算進去。

✅ 已對帳：用本檔的因子重算還原 OHLC，與已交付的 `prices/{code}.json` **逐格相同**
（上櫃 5347 共 4,940 格、上市 2330 共 4,944 格，0 不符）——
這正是「上櫃預算價已還原、瀏覽器卻只拿到僅上市因子」那條靜默分歧的封堵證明。

### 上櫃：經站內代理現場計算

TPEx 官方端點**無 CORS 標頭**，瀏覽器不能直接抓 → 上櫃的原始日K 一律走**站內代理**
（`/api/tpex/bars/*`；TPEx 對共用出口 IP 較敏感，代理層請保留逐（股, 月）快取與節流）。

還原因子已**全市場化**（上市 + 上櫃，2,104 檔 / 12,846 事件）→ 上櫃拿得到自己的
`exEvents`，還原基準與資料端一致（已對帳：用本檔因子重算的還原 OHLC 與交付的
`prices/{code}.json` 逐格相同，上櫃 4,940 格 + 上市 4,944 格 0 不符）。

🔴 **不要拿 `prices/{code}.json` 去餵現場回測**（上市上櫃都一樣）——
那份是**已還原**的顯示用資料（已捨到 4 位），實測 6.7% 組合結果會不同。
現場計算一律用代理取回的**原始** OHLC + `ex-factors.json` 自己還原。

## 4. 前端渲染要注意的語義

- **`平均持有天數` 含頭尾**：引擎定義為 `mean(xi - ei + 1)`。前端若自己用逐筆算成 `xi - ei` 會**少一天**。
- **`rc` 是索引，不是字串**：查 `out.meta.exitReasons[rc]` 取中文標籤。**不要在前端硬編這張表**，
  順序可能隨引擎版本增修（只增不重排）。
- **`skipped`**：因「訊號當天漲停、隔日開盤無法合理進場」而被跳過的訊號數。
  這是**反挑櫻桃**的誠實揭露欄位，請照實顯示，不要藏。
- **null 語義**：0 筆交易時 `勝率% / 平均報酬% / 平均持有天數 / 最大回撤%` 皆為 `null`（不是 0）。
  JS 的 `null < 5` 會把 `null` 當 0 → 排序／篩選前務必先濾掉 null。
- **權益曲線自行累乘**：`∏(1 + r/100)`，`r` 為逐筆的第 7 格（已內扣手續費與交易稅）。
- **費用內含**：買 0.1425%、賣 0.1425% + 證交稅 0.3%，已含在 `r` 與 `buyhold` 內，前端不要再扣一次。

## 5. 確認層位元圖（跑滿 450 組）

給了 `opts.confirm` 就跑滿 5 層 × 10 進場 × 9 出場 = **450 組**；不給則只跑「無」層的 90 組。

```js
import { runBacktest } from "/scripts/backtest.mjs";
import { makeConfirm } from "/scripts/chipsbits.mjs";

const bitsJson = await fetch("/data/chips-bits.json").then(r => r.json());
const bars = await fetchRawBars("2330");
const adj  = /* runBacktest 內部會還原，這裡只需要日期 */ bars.map(b => b.d);

const confirm = makeConfirm(bitsJson, "2330", adj);   // 不在位元圖內 → null
const out = runBacktest(bars, { exEvents, ...(confirm ? { confirm } : {}) });
// confirm 為 null 時 out.combos 只有 90 組，UI 須據此標示「僅基礎組合」
```

### 5.1 四個確認層的定義

| 層 | 條件 | 官方來源 |
|---|---|---|
| 無 | 不過濾 | — |
| 投信 | 投信近 **10 個交易日**累計買超 ≥ **15 張** | T86 投信買賣超股數 |
| 法人同買 | 投信達標 **且** 外資近 10 交易日淨買 > 0 | T86 外陸資 + 投信 |
| 大盤多頭 | 加權指數 > **200 日均線** | FMTQIK |
| 浮額清洗 | 融資餘額 < **20 個交易日前** | MI_MARGN 融資今日餘額 |

門檻是**照實揭露**的，不是黑箱。UI 請把這張表顯示出來，並維持「中性比較、不推薦任何一層」的敘述。

### 5.2 檔案格式

`chips-bits.json`：**1,417 檔 × 1,236 日**、889 KB（gzip 289 KB／brotli 257 KB）。
單檔即可，建議**延遲載入**（使用者真的開回測面板時才抓），瀏覽器會快取。
位元密度供參：投信 11.6%／外資 39.6%／浮額 41.8%／大盤多頭 76.7%。


```json
{
  "schema": "chips-bits/1",
  "asof": "2026-07-31",
  "trustMinLots": 15,
  "bitOrder": ["投信近10日累計買超>=15張", "外資近10日淨買>0", "融資餘額<20個交易日前"],
  "confLayers": ["無", "投信", "法人同買", "大盤多頭", "浮額清洗"],
  "dates": ["2021-07-01", "..."],          // 位元圖的欄軸（全市場交易日曆）
  "market": "<base64>",                     // 1 bit/日：加權 > 200MA（全市場共用）
  "bits": { "2330": "<base64>", "...": "" } // 每檔 3 bits/日
}
```

**編碼**：每檔對 `dates` 的每一天寫 3 個 bit，`bitOrder` 由低位到高位；所有 bit **連續**打包成
位元流（不對齊到日界），再 base64。第 `i` 天第 `k` 位的位置是 `i*3 + k`，
位在 `byte[pos >> 3]` 的第 `pos & 7` 位（**LSB first**）。`market` 同理但 1 bit/日。

**解碼**（`chipsbits.mjs` 已實作，這裡只說明原理）：

```js
const bin = atob(bits.bits["2330"]);
const bitAt = (i, k) => { const p = i * 3 + k; return (bin.charCodeAt(p >> 3) >> (p & 7)) & 1; };
// 第 i 天（i = dates.indexOf(某日）)：bitAt(i,0)=投信 bitAt(i,1)=外資 bitAt(i,2)=浮額
```

### 5.3 ⚠️ 日期對齊：一律按「日期」，不可按索引

位元是在**該股自己的交易日軸**上算好的 —— 「近 10 日」「20 個交易日前」數的是**交易日**，
不是日曆日。停牌會讓個股的 K 棒序列與市場日曆錯開（實測 2327 有 14 天停牌，
其間 T86 無資料但 MI_MARGN 仍照報融資餘額）。

所以解碼一定是：**取你手上這根 K 棒的日期 → 查 `dates` 的索引 → 讀該索引的 bit**。
拿 K 棒序號直接當位元圖索引，遇到停牌股就會整段位移。

日期不在 `dates` 裡（位元圖較舊、或該日無官方揭露）→ 該日四個 bit 全部視為 `false`。
`decodeChipsBits` 會回傳 `covered`（對得上的天數），可用來判斷資料是否過期並提示使用者。
位元圖的 `asof` 是它涵蓋的最後一個交易日；**比 `asof` 新的 K 棒一律當 false**，
若差距明顯（例如 `covered` 比 K 棒數少很多），請在 UI 標示「確認層資料截至 {asof}」而不是靜默略過。

### 5.4 上櫃與新上市：`makeConfirm` 回 `null`

位元圖來源 T86／MI_MARGN／FMTQIK **僅涵蓋上市**。上櫃個股不在 `bits` 內，
`makeConfirm` 回 `null` → 只跑 90 組。上市但歷史不足 21 個交易日者（新上市）同樣不收。

**請照實顯示「僅基礎組合（無官方籌碼確認層）」，不要靜默只給 90 組讓使用者以為是全部。**
這與資料端 `signals/{code}.json` 對上櫃 `chips = null` 的處理一致。

### 5.5 保護欄

- `confirm.layers` 含籌碼層但沒給 `confirm.series` → **拋錯**，不會靜默回傳錯的結果
- `confirm.series` 四條序列長度必須等於 K 棒數 → 否則**拋錯**（防止對齊錯位靜默算錯）
- 確認層先問、基礎訊號後問（與資料端相同）→ 被確認層擋下的訊號**不計入** `skipped`

## 6. 為什麼有 `pyround.mjs`（別想把它拿掉）

`Math.round(x*100)/100` 是**半數進位**，Python `round()` 是**半數取偶**且針對 double 的精確二進位值。
實測 19,656 個統計值有 71 個（0.36%）因此不同 → 回歸就無法 0 差。
`pyRound` 用 BigInt 精確分解 double 後做 half-to-even，已對 126,302 筆語料與 Python **逐筆完全相等**。

同理，模組內部所有加總走 `pySum`（Neumaier 補償求和），因為 **CPython 3.12+ 的內建 `sum()`
對 float 就是補償求和**。朴素左到右在 20 日均線上會差 1 ULP，實測足以讓「跌破月線」提前 3 天出場。

這兩者都不是潔癖，是**分支翻轉**的直接來源。

## 7. 驗證狀態

以 `asof 2026-07-31` 五年視窗、25 檔 × **450 組**（含全部 5 個確認層）對照資料端 Python 版：

| # | 項目 | 結果 |
|---|---|---|
| ① | **10,530 組**（25 檔 × 450）統計**逐格完全相等** | ✅ 不符 0 |
| ② | **113,756 筆**逐筆 `ep/xp/r/mae/mfe`，門檻 \|Δ\| ≤ 1e-9 | ✅ 不符 0，**最大絕對誤差 0** |
| ③ | 2330 單組合逐筆**逐位**比對（12 筆） | ✅ 12/12 完全相同 |
| ④ | `ex-factors.json` → `adjustBars` 重現還原價（113,648 格 OHLC） | ✅ 不符 0，最大誤差 0 |
| ⑤ | **端到端**：原始日K + ex-factors + 位元圖 → 現場還原 → 回測（23 檔 / **10,350 組**） | ✅ 不符 0 |
| ⑥ | 效能：單檔 450 組 | 中位 73.3ms／p90 79.9ms／最慢 81.9ms |
| ⑦ | **軸交叉驗證**：兩條獨立建置路徑的位元圖（軸 = K棒日期 vs 軸 = T86 揭露日） | ✅ 85,284 bits 逐位元相同 |

「最大絕對誤差 0」= 位元完全相同，不是「小於門檻」。

改動 `backtest.mjs`、`pyround.mjs` 或 `chipsbits.mjs` 後，**必須重跑資料端的回歸腳本並維持全數 PASS** 才能上線。
