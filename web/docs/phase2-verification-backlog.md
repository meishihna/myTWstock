# Phase 2 — 延後驗證清單

**這份文件存在的理由**:某一輪裡「記為未驗證」的項目,如果只寫在當時的回報裡,
會在輪次交替時蒸發 —— 下一輪沒有人記得它還欠著,而它看起來像已經做完了。
**所有「本輪無法驗證」的項目一律登記在此,直到它被驗證或被明文放棄。**

規則:
1. 每一項都要有**為什麼這一輪驗不了**、**要誰做什麼才驗得了**、**排在哪一輪**
2. 驗證完成後**不刪除**,改標 ✅ 並附驗證日期與證據 —— 刪掉就失去「曾經欠過」的紀錄
3. 「已驗證」不可只憑「應該沒問題」;要有實跑結果

| user | 在主控台的 Redirect URLs 加入 `https://my-twstock.vercel.app/auth/callback` |
| 我 | 線上實跑一次:點 Google → 完成授權 → 回跳 → `/trades` 顯示帳號 |

⚠️ 我**不能代為建立帳號或輸入憑證**,這幾步必須由 user 執行。

## 已知限制(Phase 2 /trades)

### 🔴 取現價時,持股代號會離開瀏覽器

**架構承諾**是「client 直連 Supabase,伺服器從不看到使用者資料」。
但取得現價必須呼叫本站的 `/api/quote-batch`,而**持股代號清單在網址的 query string 裡**
→ 會進入 Vercel 的存取記錄。累積起來就是綁在 IP 上的持股輪廓。

**這不是缺陷**(要即時報價就避不開),**但不可以是隱形的**。
`/trades` 的隱私聲明已明文寫出:「取得現價時,你持有的股票代號會傳送到本站的報價代理」。

**架構承諾與實際資料流不一致時,要改的是承諾的措辭,不是把差異藏起來。**

已查證的邊界(2026-08-14,讀 `src/pages/api/quote-batch.ts`):
| 項目 | 事實 |
|---|---|
| 記錄 | 該路由**沒有任何 `console.*` 或寫檔** |
| 持久儲存 | 無。只有單筆、60 秒 TTL 的**行程內記憶體**快取(鍵 = 排序後的代號字串) |
| 離開瀏覽器的內容 | **只有代號**。股數、成本、交易明細、損益都不會送出 |
| 回應標頭 | `Cache-Control: public, max-age=60` —— 內容以網址為鍵,不會跨使用者混淆 |

> **重訪條件:僅在改成「瀏覽器直抓報價」或「改用 POST 讓代號不進網址」時。**
> 後者成本低(存取記錄只留網址、不留 body),但 `/api/quote-batch` 是多頁共用的既有端點,
> 改動要另開一輪評估影響面 —— **不在 Phase 2 UI 主線範圍內**。

### 現價取不到時的呈現:留白,不以 0 代替

Yahoo 失敗、代號下市、報價延遲都會讓現價缺失。那時未實現損益是**未知**,不是 **0**。
- 該列的現價欄顯示「現價未取得」,市值/未實現/報酬率一律留白
- **缺價個股不併入總市值的分母**,頁尾標明「不含 N 檔未取價個股」

這是資料層那條 `null` ≠ `0` 在呈現層的延伸:**0 是資料,未知是不存在。**
實測(2026-08-14):代號 `9999` 格式合法但無報價 → 三欄留白、頁尾出現「不含 1 檔未取價個股」。

> **重訪條件:不重訪 —— 這是原則,不是待修項。**
