## 判定原則

七天的財務線打磨在此收束。分級規則:

| 分級 | 處置 |
|---|---|
| **顯示錯誤數字給使用者** | 開輪修(例:季度費用堆疊圖的負段被靜默丟棄、總高被高估 → 已修,`f9d858cd5`) |
| **資料誠實但不完整** | 記入本文件,不修 |
| **缺少解釋性標示** | 記入本文件,不修 |

「不完整」與「錯誤」的分界:**空白是誠實的,錯誤的數字不是。**
本文件列出的每一項,呈現出來的數字都是對的;缺的是完整度或解釋。

### 本文件的三條書寫規則

**① 每一項都必須有「重訪條件」。**
沒有重訪條件的已知限制會變成墳場 —— 沒人知道什麼情況該重新打開它。
而且**重訪條件是邊界,不是邀請**:寫「只在 Y 發生時重訪」正好阻止了憑感覺重開。

**② 成因未查明的必須明寫「成因未查明」。**
一份已知限制文件最不該做的事,就是**暗示它擁有它其實沒有的理解**。
凡是本站沒有實際分類過成因的項目,一律標注,不用聽起來合理的推測填空。

**③ 個股代號一律視為【舉例】,權威清單以夾具或重算規則為準。**
**散文會漂,夾具不會。** 本文件內出現的代號只是說明用的實例,不是清單;
凡需要完整名單,一律回到下列來源,不要從本文件(或任何轉述)複製:

| 名單 | 權威來源 |

## 一、資料層面

### 1.1 去累計傳染:14 格 / 12 檔

**成因:已查明**(14 格逐格對官方頁面核對過)

```
官方 ajax_t164sb04 給的是【累計】,單季由相減得出:
    Q2單季 = 累計(Q2) − 累計(Q1)

3147 的 109Q2 頁面:研究發展費用 = 5,887 仟元(累計)          ← 有
3147 的 109Q1 頁面:頁面存在,但【沒有研究發展費用那一列】   ← 累計(Q1) 未知
  → 相減算不出來 → 該季交付 null
```

14 格全部是這個形狀:**自己那期的頁面有累計值,前一期的頁面存在但缺該科目列。**

**為什麼不補救**:唯一的補法是把「前一期沒有那一列」當成 `0`,然後 `Q2單季 = 累計(Q2) − 0`。
那違反本專案一路守住的 **`null` ≠ `0`**(見 `financials-contract.md`「🔴 `null` ≠ `0`」)。
「該公司當期未揭露此科目」與「該科目金額為零」是兩件事,把前者寫成 0 會製造一個
看起來正常、實際上是我們發明的數字。**寧可留白。**

> **重訪條件:永久,不重訪。** 除非「未揭露可否在特定條件下視為 0」這個原則層問題
> 被重新裁決 —— 那是獨立議題,不是這 14 格的問題。

### 1.2 語義 null:21 格 / 8 檔

**成因:已查明**(21 格逐格確認官方該期損益表無該科目列,例:1604 的管理費用在 2018–2019 各期皆無此列)

`null` 是正確呈現,不是缺漏。

> **重訪條件:永久,不重訪。** 官方沒有那個科目,沒有可補的東西。

### 1.3 🔴 同一家公司會跨年度改變科目揭露方式

**成因:已查明**(逐頁核對)

**1612 華新的實例**:`管理費用` 在民國 113 年度頁面有列(13,434 仟元),
114 年度頁面**沒有那一列**。同一檔、同一科目,前者是解析缺口(已交引擎修)、後者是語義 null。

**推論(對日後任何 parser 或稽核都成立)**:
不能以「公司」為單位判定「這家公司有沒有這個科目」,必須**逐期別**判定。
以公司為單位的白名單/黑名單,會在改制那一年整批判錯。

> **重訪條件:不重訪 —— 這不是待修項,是一條設計約束。**
> 它的用途是防止日後有人寫出以公司為單位的判定邏輯。

### 1.4 官方勝出但該欄全空 → 整欄留白:8 檔(2026-08-13 新增)

`resolveGroups()` 改為【期別覆蓋】規則後,官方勝出時該群組**含 `null` 一律以官方為準**,
不再因為某個欄位官方全空就退回 store。實測 8 檔落入此情形:

```
2329 · 2367 · 2453 · 3026 · 5211 · 5489 · 8112 · 9926
官方損益表沒有「管理費用」那一列 → 該欄整欄留白(圖上只畫推銷 + 研發)
```

**為什麼不讓 store 補**:store 的 `General & Admin Exp` 實為【營業費用合計】。
補進來會變成 推銷(官方) + 研發(官方) + 營業費用合計(store) = **重複計算**,
而且同一張圖混來源。**留白是誠實的,重複計算不是。**

> **重訪條件:僅在官方日後開始揭露這 8 檔的管理費用時自動消失,不需人為重訪。**

### 1.8 🔴 「解析缺口已修完」量不到 —— 偵測器與被測對象共用上游過濾器(2026-08-19 新增)

**成因:結構性,已查明。**

上面「✅ 已修復」表列的 21 格解析缺口、以及 11 檔的原始申報回填,
**發現方式是拿官方交付檔去比對 `data/financials_store`**:store 有值、官方為 `null` 的格子才會亮起來。

於是有一整類格子**從來不會亮**:

| 官方 | store | 偵測器 |
|---|---|---|
| 有值 | — | 不需要偵測 |
| `null` | **有值** | ✅ 亮起來 → 這 21 格就是這樣找到的 |
| `null` | **也 `null`** | 🔴 **不會亮。「真的沒有這個科目」與「兩邊都漏抓」輸出一模一樣** |

**這與 `attack 0 + control 0` 是同一個病**:在正確與錯誤假設下都會通過的檢查,不是檢查。
差別只在這裡的對照組不是我們選的,是資料本身沒給。

#### 盲區的大小(2026-08-19 實測,年度區塊、雙方都有的年份、四欄)

```
可比對個股 1,627 檔(另有 348 檔無 store 或形狀不符 → 整檔零鑑別力)

欄位     官方有值      官方null·store有值    官方null·store也null
                       = 可偵測              = 🔴 盲區
sell     11,807 93.5%     82  0.6%            733   5.8%  (111 檔)
admin    12,072 95.6%    542  4.3%              8   0.1%  (  1 檔)
rd       10,051 79.6%    616  4.9%          1,955  15.5%  (345 檔)
capex    12,313 97.6%    141  1.1%            168   1.3%  ( 50 檔)

合計:可偵測區 1,381 格 · 盲區 2,864 格 —— 盲區是可偵測區的 2.1 倍
```

**盲區裡絕大多數八成真的是語義 null**(那家公司真的沒有研發費用那一列)。
**但那是推測,不是量測** —— 本站沒有任何獨立來源能區分這 2,864 格哪些是真沒有、哪些是兩邊都漏。

#### 所以下列讀法是錯的

| ❌ 不可以讀成 | ✅ 實際成立的 |
|---|---|
| 「解析缺口已清零」 | 「**store 看得見的那一類**解析缺口已清零」 |
| 「官方交付檔已無漏抓」 | 「漏抓率在 1,381 格的可偵測區內為 0;另有 2,864 格無從判斷」 |
| 「那 11 檔已完全一致」 | 「那 11 檔在 store 有值可作對照的範圍內一致」 |

**額外一層**:`admin` 的對照本身口徑不同 —— store 的 `General & Admin Exp` 實為
【營業費用合計】(見 §1.4)。所以 `admin` 那一欄的「可偵測」也比看起來弱:
它比的是兩個定義不同的東西,只是恰好都非空。

> **重訪條件(兩條,任一成立即重訪):**
> **(a)** 引擎日後對**全體** 1,975 檔做原始申報的全量科目枚舉 —— 也就是
> **不再拿 store 當篩選器**、改為逐檔逐期直接枚舉官方頁面上實際存在的科目名。
> 那是唯一能把這 2,864 格從「無從判斷」變成結論的做法。
> **(b)** 出現外部證據(使用者回報、法說會簡報、年報)指向某檔某期官方有值而本站為 `null`。
>
> **不重訪的情況:單純想「再確認一次」。** 用同一組來源重跑,只會再得到同一個 0。

## 三、工程層面

### 3.1 `.astro` frontmatter 沒有型別閘

**成因:已查明**(政策選擇)

`astro check` 需要把 `@astrojs/check` 加進 devDependencies,而本專案**刻意零 devDependencies**
(工具一律 `npx --yes`)。因此 `.astro` 檔的 frontmatter 目前不在 `tsc --noEmit` 的涵蓋範圍。

替代證據(以 `FinancialDashboard.astro` 的堆疊圖幾何為例):
`.ts` 模組的 `tsc --noEmit`、production build、dev server 與**建置產物**的逐格量測(誤差 0)。

> **重訪條件:僅在下次因別的理由要動 `FinancialDashboard.astro` 時順手做**
> (把 `stackedExpensePctSvg` 抽到 `src/lib/` 成為 tsc 可檢的模組)。
> **不為此單獨開輪** —— 這段幾何邏輯已由多層實測背書,型別閘的邊際價值不高。

### 3.2 收貨宣告必須涵蓋「補抓年」與「補抓年 − 1」

**成因:已查明**(MOPS 端點的形狀)

`ajax_t164sb04` 一次回**兩期**。所以引擎去補民國 107 年,回來的頁面同時帶著民國 106 ——
只宣告 `1434:107` 的話,**106 年那些格子的變動會落在宣告範圍外**,
而它們是同一次抓取的必然產物,不是額外的改動。

`tests/check-115-additive.mjs` 的 `parseAllowRestate()` 因此**自動把 (檔, 民國Y) 展開成 {Y, Y−1}**。

🔴 **兩條配套約束,少一條這個展開就變成漏洞:**
1. **展開後的完整範圍一定印出來**,不靜默生效 ——
   「自動放寬」若不可見,下一個人會以為他宣告的就是他看到的。
2. **萬用通行證一律拒收**(`*:113` / `1101:*` / `1101` / `*` 都會拋錯)——
