## 判定原則

七天的財務線打磨在此收束。分級規則:

| 分級 | 處置 |
|---|---|
| **顯示錯誤數字給使用者** | 開輪修(例:季度費用堆疊圖的負段被靜默丟棄、總高被高估 → 已修,`f9d858cd5`) |
| **資料誠實但不完整** | 記入本文件,不修 |
| **缺少解釋性標示** | 記入本文件,不修 |

「不完整」與「錯誤」的分界:**空白是誠實的,錯誤的數字不是。**
本文件列出的每一項,呈現出來的數字都是對的;缺的是完整度或解釋。

### 本文件的三條書寫規則

**① 每一項都必須有「重訪條件」。**
沒有重訪條件的已知限制會變成墳場 —— 沒人知道什麼情況該重新打開它。
而且**重訪條件是邊界,不是邀請**:寫「只在 Y 發生時重訪」正好阻止了憑感覺重開。

**② 成因未查明的必須明寫「成因未查明」。**
一份已知限制文件最不該做的事,就是**暗示它擁有它其實沒有的理解**。
凡是本站沒有實際分類過成因的項目,一律標注,不用聽起來合理的推測填空。

**③ 個股代號一律視為【舉例】,權威清單以夾具或重算規則為準。**
**散文會漂,夾具不會。** 本文件內出現的代號只是說明用的實例,不是清單;
凡需要完整名單,一律回到下列來源,不要從本文件(或任何轉述)複製:

| 名單 | 權威來源 |
|---|---|
| 三分類(解析缺口 / 去累計傳染 / 語義 null) | `web/tests/fixtures/lost-cells-classified-20260811.json` 的 `verdict` 欄 |
| 髮絲段(畫得比 1px 還小的段) | 依 §2.2 的規則重算:該段上緣到堆疊邊界的距離 < 1px 時,下限被封頂 |
| 負費用 / 負營收 / 零營收 / 金融業 CAPEX / 現金流量級 | 依文末「量測方式」的定義重算 |

**實例(2026-08-11,轉述出錯的實況)**:口頭轉述解析缺口那 11 檔時,
我照著**被截斷的 console 輸出**(每類只印前 12 列)用眼睛抄,結果跨類混抄 ——
把 `2438 / 2514 / 6225`(實際屬於「語義 null」)當成解析缺口,漏掉 `2348 / 3115 / 6264`。
引擎側因為讀的是夾具而沒受影響。**清單只要被人手複製過一次,就開始漂。**

## 一、資料層面

### 1.1 去累計傳染:14 格 / 12 檔

**成因:已查明**(14 格逐格對官方頁面核對過)

```
官方 ajax_t164sb04 給的是【累計】,單季由相減得出:
    Q2單季 = 累計(Q2) − 累計(Q1)

3147 的 109Q2 頁面:研究發展費用 = 5,887 仟元(累計)          ← 有
3147 的 109Q1 頁面:頁面存在,但【沒有研究發展費用那一列】   ← 累計(Q1) 未知
  → 相減算不出來 → 該季交付 null
```

14 格全部是這個形狀:**自己那期的頁面有累計值,前一期的頁面存在但缺該科目列。**

**為什麼不補救**:唯一的補法是把「前一期沒有那一列」當成 `0`,然後 `Q2單季 = 累計(Q2) − 0`。
那違反本專案一路守住的 **`null` ≠ `0`**(見 `financials-contract.md`「🔴 `null` ≠ `0`」)。
「該公司當期未揭露此科目」與「該科目金額為零」是兩件事,把前者寫成 0 會製造一個
看起來正常、實際上是我們發明的數字。**寧可留白。**

> **重訪條件:永久,不重訪。** 除非「未揭露可否在特定條件下視為 0」這個原則層問題
> 被重新裁決 —— 那是獨立議題,不是這 14 格的問題。

### 1.2 語義 null:21 格 / 8 檔

**成因:已查明**(21 格逐格確認官方該期損益表無該科目列,例:1604 的管理費用在 2018–2019 各期皆無此列)

`null` 是正確呈現,不是缺漏。

> **重訪條件:永久,不重訪。** 官方沒有那個科目,沒有可補的東西。

### 1.3 🔴 同一家公司會跨年度改變科目揭露方式

**成因:已查明**(逐頁核對)

**1612 華新的實例**:`管理費用` 在民國 113 年度頁面有列(13,434 仟元),
114 年度頁面**沒有那一列**。同一檔、同一科目,前者是解析缺口(已交引擎修)、後者是語義 null。

**推論(對日後任何 parser 或稽核都成立)**:
不能以「公司」為單位判定「這家公司有沒有這個科目」,必須**逐期別**判定。
以公司為單位的白名單/黑名單,會在改制那一年整批判錯。

> **重訪條件:不重訪 —— 這不是待修項,是一條設計約束。**
> 它的用途是防止日後有人寫出以公司為單位的判定邏輯。

### 1.4 官方勝出但該欄全空 → 整欄留白:8 檔(2026-08-13 新增)

`resolveGroups()` 改為【期別覆蓋】規則後,官方勝出時該群組**含 `null` 一律以官方為準**,
不再因為某個欄位官方全空就退回 store。實測 8 檔落入此情形:

```
2329 · 2367 · 2453 · 3026 · 5211 · 5489 · 8112 · 9926
官方損益表沒有「管理費用」那一列 → 該欄整欄留白(圖上只畫推銷 + 研發)
```

**為什麼不讓 store 補**:store 的 `General & Admin Exp` 實為【營業費用合計】。
補進來會變成 推銷(官方) + 研發(官方) + 營業費用合計(store) = **重複計算**,
而且同一張圖混來源。**留白是誠實的,重複計算不是。**

> **重訪條件:僅在官方日後開始揭露這 8 檔的管理費用時自動消失,不需人為重訪。**

### 1.5 金融業 CAPEX 全空:31 檔 / 1,153 個期別格

`industryType` 為 `fh` / `bank` / `ins` / `sec` 的個股中,31 檔的 `capex` 在**所有期別**皆為 null。
(2026-08-13 由 39 檔降為 31 檔:證券業 8 檔已於本輪補上。)

**成因:未查明。** 本站只量到「這 31 檔全空」,**未逐檔回官方頁面確認**
官方現金流量表是否真的沒有對應科目。合理的假設是有的,但那是假設,不是查證。

> 引擎側先前回報「41 檔 / 656 格 / 2.3%」,與本文件的 31 檔 / 1,153 格差異來自口徑
> (本文件計「該檔所有期別列數」,引擎側計的是另一種分母)。兩者都指同一件事,不影響結論。

> **重訪條件:僅在他日開「4d 金融業口徑」時一併處理,否則不重訪。**
> 屆時第一件事應是逐檔核對官方頁面,把成因從「未查明」變成結論。

### 1.6 保險業:6 檔

`industryType === "ins"` 共 6 檔,部分欄位留白。

**成因:未查明。** 常見說法是 IFRS 17 之後保險業損益表結構與其他業別不同、
本站欄位映射不涵蓋其特有科目 —— **本站未實際核對過**,不當作結論寫。

> **重訪條件:僅在他日開「4d 金融業口徑」時一併處理,否則不重訪。**

### 1.7 現金流量級異常大:1,067 格 / 97 檔

`rev > 0` 且 `|ocf|` 或 `|icf|` 或 `|fcf|` 超過該期營收 50 倍者。

**🔴 成因:未查明。** 本站**只做了計數,從未分類過這 1,067 格的成因**。
數字本身通過了交付檔的其他檢查(符號、量級、逐格對照),沒有已知的錯誤;
但「為什麼會這麼大」我們沒有答案,也不應該用聽起來合理的說法填空。

> **重訪條件:僅在有具體個股被回報「現金流數字看起來不對」時重訪,否則不重訪。**

### 2.2 費用堆疊圖:最外層髮絲段看不見

**成因:已查明**(是設計取捨,不是缺陷)

1px 可見性下限受【該段上緣到堆疊邊界的距離】封頂:正段不得越過 0% 基線、
負段不得越過負堆底端。這是為了讓「畫出來的總高 == 三段真實和」精確成立
(下限若把端點推出去,實測誤差達 0.26pp)。

代價:貼著邊界的髮絲段(< 1px,約 < 0.3% 營收)會小到看不見。
**實例**:1465 的 2020Q4 管理費用率 −0.0642%,畫成 0.198px。數值仍完整呈現在 tooltip;總高精確。

🔴 2026-08-13 修正:下限改為受【該段上緣到堆疊邊界的距離】封頂 ——
正段不得越過 0% 基線、負段不得越過負堆底端。原本的「排除最貼邊那一段」不夠 general:
第二段正值撐成 1px 時,若第一段本身不足 1px,溢出照樣穿過基線(全站掃描抓到 17 個期別 / 5 檔)。
受影響的個股清單請依此規則重算,本文件不列舉(見書寫規則③)。

> **重訪條件:僅在使用者實際反映「有一段看不到」時重訪,否則不重訪。**
> 任何補救都必須先回答「總高還等不等於真實和」—— 那條硬約束不可為了可見性讓步。

## 附:量測方式

本文件的數字除註明「引擎側量測」者外,皆由本站自行清點(2026-08-11 首次;
受本輪 parser 修復與期別覆蓋規則影響者已於 2026-08-13 重量),定義如下:

- **負費用格**:adapter 輸出的季度區塊中,`rev > 0` 且三費任一 `< 0` 的格(報告頁 1,737 檔範圍)
- **負/零營收格**:交付檔 `annual` + `quarters` 兩區塊中 `rev` 為有限值且 `< 0` / `== 0` 的格(1,975 檔全範圍)
- **金融業 CAPEX 全空**:`industryType ∈ {fh, bank, ins, sec}` 且 `capex` 在所有期別皆非有限值
- **現金流量級**:`rev > 0` 且 `|ocf|` 或 `|icf|` 或 `|fcf|` `> 50 × rev`

⚠️ 掃描範圍會改變數字:1,737 檔(有報告頁)與 1,975 檔(交付檔)相差約 15%。
引用本文件的數字時請一併引用範圍。

**實例**:同一組負營收數字,在 1,737 檔範圍下是 58 格 / 25 檔,在 1,975 檔範圍下是 65 格 / 32 檔。
兩者都對,差的只是母體。**不標範圍的數字,下次一定會再吵一次。**
