# tests/

## reconcile-live.mjs — 現場回測對帳

驗證「瀏覽器現場計算」的結果與資料端預先算好的 `public/data/signals/{code}.json`
**逐格完全相同**。這是整條現場回測功能的信任基礎。

### 為什麼要進版控

S2 階段量到的「0 差」若只存在於一次性執行裡,日後改了 `backtest.mjs` / `twsebars.mjs` /
`chipsbits.mjs` 就無法複驗 —— 等同沒有測試。腳本與輸入(夾具)都必須留在版控。

### 重跑

```bash
cd web

# 預設:離線,用版控夾具,0 次官方請求(CI 可直接跑)
node tests/reconcile-live.mjs

# 單檔
node tests/reconcile-live.mjs 2330

# 真的打官方端點(節流 350ms,約 20–30 秒/檔)
node tests/reconcile-live.mjs --live

# 打官方端點並【更新夾具】—— 只有資料端換 asof 後才需要
node tests/reconcile-live.mjs --record
```

退出碼:`0` = 全部 PASS,`1` = 有任一項不符或夾具問題。

### 涵蓋的個股(刻意選的)

| 代號 | 為什麼選它 |
|---|---|
| **2330** 台積電 | 基準檔,1,236 根 |
| **2327** 國巨\* | **有 14 天停牌**(1,222 根,比 2330 少 14)—— 專門驗**日期對齊**。位元圖是在「該股自己的交易日軸」上算的,若用 K 棒序號當索引,遇停牌就會整段位移 |
| **2317** 鴻海 | 第三檔上市股,增加廣度(1,235 根) |

### 這支測試實際檢查什麼

- 統計逐格(450 組 × 10 欄)、逐筆逐格(`si/ei/xi/ep/xp/rc/r/mae/mfe`)、`buyhold`
- 權益累乘 `∏(1+r/100)` 是否等於引擎的 `總報酬%`
- 確認層 `covered`(位元圖涵蓋天數)
- **離線模式注入會拋錯的 `fetch`** → 任何一次網路存取都會讓測試失敗,
  確保「0 次網路」不是宣稱而是被強制的

### 設計上的兩個堅持

1. **import 實際會上線的模組**(`public/scripts/*.mjs`),不用複製品。
   測複製品等於沒測到會出貨的那份程式碼。
2. **離線可重跑**。每次全量 live 執行 = 183 次官方請求,對端點不禮貌也不可靠
   (實測連抓時官方會**間歇性失敗**:2327 的 202209、2317 的 202203 都曾在整批中失敗,
   但失敗後立刻單獨請求同一網址即回 200/OK)。

### 夾具

`fixtures/bars/{code}.json` — 原始**未還原** STOCK_DAY 日K(已解析),每檔約 80KB。

> ⚠️ 餵給引擎的必須是**原始日K + ex-factors**。
> `public/data/prices/*.json` 是**顯示用**、已捨入到小數 4 位,
> 實測會讓 **6.7%** 的組合統計不同(分支翻轉,不是誤差累積)。

夾具的 `asof` / `months` 與 `signals-index.json` 的 `window` 不符時會直接報錯要求 `--record`。
