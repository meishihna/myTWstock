## 為什麼這次「伺服器代抓」不踩重散布紅線

| | FinMind(已移除) | TPEx(本案) |
|---|---|---|
| 性質 | 私有第三方服務 | **政府機關**(證券櫃檯買賣中心)開放資料 |
| 授權 | 條款不明、需個人 token | **政府資料開放授權條款**:允許重製、散布、公開傳輸,**須標示來源** |
| 我們做的事 | 用個人 token 抓 → commit 進公開 repo → 對外可下載 | 代抓 + 快取,**不落地進 repo** |

紅線原文是「平台不得『伺服器抓 → 快取/落地 → 供所有訪客』」,當時針對的是
**私有服務且條款不明**的資料。政府開放資料明示允許重製散布,代理是被允許的。

**義務**:UI 與 API 回應都要標示來源(規劃內已含 `X-Data-Source` 標頭 + 前端來源文字)。

## ② 快取設計(硬要求)

### 路由

```
web/src/pages/api/tpex/bars/[code]/[ym].ts     GET  → { stat, code, ym, unit:"shares", bars:[{d,o,h,l,c,v}] }
export const prerender = false;
```

一個月一條路徑(不是 query string)是刻意的:**路徑進 CDN 快取鍵最乾淨**,
不必擔心 query 順序或多餘參數造成快取分裂。

### 三層快取

| 層 | 做法 | 理由 |
|---|---|---|
| ① **CDN / 邊快取** | 歷史月:`Cache-Control: public, max-age=0, s-maxage=31536000, immutable, stale-while-revalidate=86400`<br>當月:`s-maxage=600, stale-while-revalidate=3600` | 收盤後不再變的月份,全站所有使用者共用**同一次**上游請求 |
| ② **瀏覽器 IndexedDB** | 沿用 `twsebars.mjs` 既有的 `getCached/putCached`(逐月) | 同一使用者重算不再打伺服器 |
| ③ **函式內記憶體** | `Map<key, Promise>` in-flight 去重 | 見下方併發防護 |

⚠️ **現有 API 路由全部只用 `max-age`,沒有一支用 `s-maxage`**
(`api/quote/[ticker].ts`、`market-ticker.ts`、`news.ts` 皆是 `public, max-age=N`)。
→ 這支是**第一個真正依賴 Vercel 邊快取的路由**,`s-maxage` 是否生效**必須在 preview 實測**
(看回應的 `x-vercel-cache: HIT/MISS`),不可假設。

**「歷史月」的判定**:`ym < 當月`(以台北時區 UTC+8 判斷,不可用 UTC —— 月初會差一天)。
當月即使已收盤也用短 TTL:更正資料會回填。

### 併發防護(多人同時算同一檔不可放大成多次上游請求)

```
單一函式實例內:in-flight Map<`${code}|${ym}`, Promise<Result>>
  → 同一實例的並發請求共用同一個上游 fetch
跨實例:靠 CDN 快取收斂(第一個 MISS 打上游,其餘等 CDN)
```
🔴 **誠實揭露其極限**:Vercel serverless 是多實例的,in-flight Map **只在單一實例內有效**。
真正的跨實例互斥需要外部鎖(KV/Redis),而 Phase 2 的裁決是 **$0 月費**,不引入付費服務。
→ 冷啟動時最壞情況是「同時有 N 個實例各打一次上游」。用**節流 + 單月粒度**把 N 壓小:
每個瀏覽器一次只需 61 個不同月份、且 `twsebars.mjs` 已有 `gapMs` 節流(預設 350ms)。
若實測發現被擋,再考慮 ⑤ 的退場方案。

### 上游失敗:大聲回錯,不回半份

沿用 `twsebars.mjs` 既有的鐵律(檔內註解):
- 單月失敗 → 指數退避重試 3 次(2s/4s/8s)
- 仍失敗 → 回 **502 + `{stat:"error", reason}`**,`Cache-Control: no-store`
  🔴 **絕不可把失敗的月份當成「該月無交易」跳過** —— 少一個月 = 視窗不完整 = 數字錯但看起來正常
- 「該月真的無資料」(如個股當時尚未上櫃)→ `{stat:"ok", bars:[]}`,與失敗**明確區分**

## ④ 驗收設計

### 4-a 對帳(前置完成後才有意義)

```
一檔上櫃 5347:現場算 90 組  vs  預算 signals/5347.json 逐格
```
**前置**:引擎交付上櫃因子(見 §0)。在那之前這條對帳**必然不是 0 差**,
而且差的原因是除權息還原,不是代理。

**另外兩個必須先對齊的口徑**(否則就算有因子也不會 0 差):
1. **成交量單位 = 股數,已定案** —— 引擎端的上櫃日K 管線明載「量仟股 ×1000 對齊 TWSE 股」,
   故 `prices/*.json` 的上櫃量已是**股數**;瀏覽器 parser 必須同樣 ×1000。
   **已實測驗證**(5347 民國115年7月,22 根):TPEx 原始張數 vs `prices/5347.json` 的 `v`,
   比值 min=1000.00 max=1000.00,**22/22 全部恰為 1000**。→ 不再是交接問題。
2. **無成交日的剔除規則** —— TWSE parser 是「收盤 `--`/空/0 → 剔除」。TPEx 的
   無成交日長什麼樣(`--`?`0.00`?整列缺?)需要抓一個有停牌的月份確認。
   (可比對:`prices/5347.json` 1,235 根 vs `prices/2330.json` 1,236 根,**差 1 根** ——
   5347 有一天沒有資料,正好可以當對齊測試的靶。)

### 4-b 離線可重跑(沿用 S2 的成功做法)

把 5347 的 61 個月 TPEx 原始回應固化成夾具進版控:
```
web/tests/fixtures/bars/5347.tpex.json     ← 原始 tables[0].data,不是解析後的
web/tests/reconcile-live.mjs               ← 加上櫃案例,注入 throwing fetch 確保 0 次網路
```

### 4-c 代理層自己的測試

| 測試 | 判準 |
|---|---|
| 歷史月回應標頭 | 含 `s-maxage=31536000`,且 preview 上第二次請求 `x-vercel-cache: HIT` |
| 當月回應標頭 | `s-maxage=600` |
| 上游 500/timeout | 回 **502**,`Cache-Control: no-store`,**不得**回 200 空陣列 |
| 上游回 `stat!=ok` | 區分「無資料」與「異常」,前者 200 空陣列、後者 502 |
| JSESSIONID | 回應**不含** `Set-Cookie` |
| 代號白名單 | `/^\d{4}$/` 以外一律 400(避免被當成任意 URL 轉發器) |
| 月份範圍 | 只接受 `YYYYMM` 且在 `[2015-01, 當月]`,超界 400(避免被拿去爆打上游) |

## ⑤ 風險與退場

### 風險 1:TPEx 擋伺服器 IP

Vercel 的出口 IP 是共享的,可能已被其他人打過。**徵兆**:429 / 403 / 連線重置。

退場方案,由輕到重:
1. **加大節流**(單一函式實例內序列化 + `gapMs` 拉到 1,000ms)
2. **只允許自選股**(現況就是自選股才會現場算 → 上限天然受限)
3. **改為「排隊預算」**:使用者按下後由 CI 排程算,算完進 `signals/`,不即時回應
   —— 犧牲即時性但零上游壓力
4. **放棄上櫃現場算**,回到現況(`stab off`)。既有功能不減少,只是沒有新增。

⚠️ **不做**的退場:偽造 User-Agent 輪替、走第三方代理池 —— 那是規避封鎖,不是正當使用。

### 風險 2:Vercel 額度

**請求數估算(這是可以算的部分)**:
```
單一使用者算一檔上櫃 = 61 個月 × 1 次 = 61 次函式呼叫(全 MISS 的最壞情況)
命中 CDN 後 = 0 次函式呼叫(邊快取直接回)
全市場上櫃 891 檔 × 61 月 = 54,351 個唯一 (code, ym) → 這是【上限】,
  因為歷史月 immutable,每個組合終生只需 1 次函式呼叫
實務上:自選股才會算,假設常用 50 檔上櫃 → 3,050 次函式呼叫(一次性)
        之後每月新增 = 50 檔 × 1 月 = 50 次
```

**額度本身我不敢從記憶斷言** —— Vercel Hobby 的函式呼叫數/GB-hours 上限請你在
dashboard 確認後填入(Phase 2 已裁決維持 Hobby、月費 $0)。上面的請求數才是重點:
**因為歷史月不變,總量是收斂的而非隨流量線性成長**。

### 風險 3:代理被當成開放轉發器

已在 ④ 的白名單(代號 4 碼 + 月份範圍)處理。額外:
- 只接受 `GET`
- 不回傳上游的任何標頭(自己組)
- 不接受任何來自 query 的 URL 片段
